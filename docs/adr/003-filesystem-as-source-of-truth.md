# ADR-003: 本地文件系统是唯一事实源

> Status: Accepted（Amended by ADR-007） | Date: 2026-10-23 | Deciders: 项目所有者 | 关联 RFC: RFC-001 §3、§4.1、RFC-006 §4.4 | 影响：数据模型、启动流程、外部编辑兼容性

## Context

笔记应用通常面临「数据库索引 vs 直接读写文件」的选择。MD Studio 的定位是本地优先的 Markdown 写作工具，用户很可能同时用 Typora、VS Code 或 Git 管理同一批文件。若应用维护独立数据库，外部修改会造成索引过期、内容覆盖或迁移负担。

## Decision

1. **不建数据库、不缓存正文**。工作区根路径是唯一持久化配置，保存在 `localStorage` 的 `mdstudio.workspace`；笔记内容每次从磁盘读取。
2. **启动时重新扫描**工作区，文件树以本次扫描结果为准；不监听文件系统变化（MVP）。
3. **保存直接写回原文件**，采用 UTF-8 文本；不改变换行符之外的格式，不做 Markdown 规范化。
4. **不做冲突检测**：同一文件被外部修改后，应用内下一次保存会覆盖磁盘内容；该风险记录在 backlog B1-4。
5. 所有笔记操作以「工作区根 + 相对路径」表达，Rust 侧负责拼接与校验，前端不持有绝对路径写权限。

## Alternatives

- **SQLite 索引 + 正文入库**：搜索更快，但需要处理外部修改、迁移、备份与双写一致性；对 MVP 是负债。
- **内存缓存 + 定时落盘**：崩溃会丢数据，且与外部编辑器冲突更隐蔽。
- **文件监听 + 增量索引**：体验更好，但跨平台监听语义复杂（重命名、原子保存、网络盘），留到有真实需求时再引入。
- **云同步优先**：需要账号与服务端，超出本地工具定位。

## Consequences

- 正：与 Typora/VS Code/Git 天然兼容，用户可随时绕过应用修改文件。
- 正：没有数据库迁移与损坏恢复问题，备份就是复制文件夹。
- 正：实现与测试都更简单，Rust 侧只需文件读写。
- 负：大目录首次扫描有延迟；搜索只能基于文件名/路径（全文搜索列入 backlog）。
- 负：无冲突检测，外部并发编辑可能被覆盖。
- 风险：未来加入标签、全文索引时，需要重新评估是否引入派生索引。触发条件：工作区文件数 > 5000 或搜索延迟 > 200ms。

## Amendment

- 2026-10-23（ADR-007）：Decision 1 的「不缓存正文」限定为「不建持久化正文库」。进程内只读快照属于缓存而非事实源：写入前仍读盘比对 revision（ADR-005），监听失败时以 mtime+size 校验，切换工作区或退出即丢弃。事实源仍是磁盘，架构定位不变。
